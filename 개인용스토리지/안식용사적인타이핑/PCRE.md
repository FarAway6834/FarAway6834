## 1. PCRE2의 문자열 처리 환경에 대한 간략한 확인

다소 부정확할수 있지만, 그냥 인코딩을 몇개 지원해서, "그 넓이 알아서 유저가 명시해놓으면"(PCRE2_CODE_UNIT_WIDTH에 명시), 그다음엔 알아서 하는(=감안하고 문자열 사용법을 합의본, 그러나 런타임에 지랄염병하진 않는) 아키텍쳐라 하면 되지만...

대충 인코딩 몇개 지원한다. 그리고 그 인코딩에 맞는 문자열용 자료형 있을거다. 

```
이 글에서 쓰이지만, 설명 안해줄태니까 알아서 이해해야하는 세가지 term(개념(concept), 용어(단어(word)))에 대해서 먼저 간략히 지칭해놓겠다.
 - 고정 크기 환경 (Fixed-width Env) : 코드 유닛[^1] 1개 = 글자[^2] 1개인 환경
 - 가변 크기 환경 (Variable-width Env) : 고정 크기 환경에서 말한 공식이 성립하지 않는 환경이다.
 - 크기 환경은 인코딩에 따라 정해지는거라는 사실
 - 쉽게 말해서 ; 컴퓨터는 공장에서 찍어낸것 같은 래고블럭같이, 정해진 정보크기의 데이터를 다룬다는 펙트를 알지 않는가? 이제 그 정해진 정보크기 단위를 하나의 래고처럼 대상취급한다. 뭐 누구나 알겟지만. 암튼 그래서, 어떻게 저쩧게 그 래고를 내부적으로 쪼개서 관리하든 아주 잘 하든 해서, 우리가 쓰는 정상적인 글자 한 자를, 래고 하나로 저장하거나, 여러가지에 존나 아주 잘 뭔가 절차(알고리즘)을 대충 아주 잘 해줘서 가변적인(=수치가 알잘딱깔센인...여기서는 레고 갯수 수치를 말하는거다.) 래고 갯수로 처리하던가 한다는거다.

[^1]: 이 글을 읽으려면 코드 유닛은 알고있어야 한다. 근데 사실, C언어의 처리방식을 알고있다면 (한 권으로 읽는 컴퓨터 구조와 프로그래밍이라는 책을 이해해보는걸 먼저 추천.) 이해가 쉽다. 컴퓨팅을 할떄, 메모리에서 데이터를 한 번에 읽고 쓰는 물리적인 비트(bit) 단위 크기로, Code Unit은 컴퓨터가 문자 데이터를 처리하기 위해 메모리에 할당하는 "가장 작은 물리적 데이터 저장 단위"고, 부호화 단위라고도 한다. C가 자료형으로 저장하는 자료(데이터) 들은 대부분 상식적으로 바이트 단위 고정 크기이므로, 무조건 byte크기인 Code unit이 바로 size가 고정된 C적인 자료라 할수 있다. 대표적으로 char을 코드 유닛으로 하는 char배열이 있고, 사실 char배열을 ascii로 다루는 고정크기환경이, 가장 정석적인 예라 할수 있다. 그래서 char도 이해해보도록 해보길 추천한다.
[^2]: 글자(character)는 사실 python에서 ord/chr로 유니코드로써 한번 다뤄보면 감이 온다. 그래도 이 글을 읽으려면 글자라는것이 어떤 단위인지 알고있어야한다. 그냥 인간이 보는 한 자를 글자라 한다. 물론 완성형이 아닌 조합형 글자를 쓴 경우에는 뭐.... 해명 안해버릴래.

아니 젠장 이제 쓸일이 없어졌어. 기껏 배웠는데, 알고보니 그냥 인코딩을 다양이 지원한다는 점에 함의되어있는 좆같은 미사여구를 공부한거였어.
```

3시간 태웠는데 시발, 존나 자명하잖아 젠장할 재미니, 책으로는 1분걸리는걸, 그놈이 실전 이해하라고 강요하느라 씨발

암튼, 크기 환경을 미쳤다고 런타임에 분기하겠는가? 당연히, 동적인것처럼 보이는건, PCRE용 DEFINE 상수 `PCRE2_CODE_UNIT_WIDTH`를 이용해서 메크로로 구현하는 C다운 수작을 부린거다.

뭐, 수작을 부려서, 실질적으로는 길이를 합의하고 인코딩을 합의해서 라이브러리를 쓰는것처럼 보이게 된다.

씨발 이걸 알려고, "왼만한 데이터는 뭔 인코딩자식으로 해석되는데, 그걸 대충 신박한(고전적인데 왜 정적으로 동적을 처리하면 신박한 대상으로 책에서 서술함 ㅅㅂ) 수작으로 멀티바이트/멀티인코딩 지원 환경마냥 만들어놓은것"이라는 말을 이해해보려 지랄염병을 떨었다만,

그건 그냥 여러 인코딩을 다루는 PCRE를 심화응용하는 진또배기 사용을 할때 배울일이지, 여기서 소개할 내용이 아니다.
